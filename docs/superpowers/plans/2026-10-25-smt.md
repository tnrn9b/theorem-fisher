# SMT Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

(Restored on 14 Nov 2026 from the session that wrote it; executed 25 Oct 2026. The original commit lived only in a cloud mirror.)

**Goal:** Give Fisher an SMT solver three ways: lean-smt's `smt` tactic as a pre-pass arm, solver countermodels feeding the existing disproof stage, and an `smt_check` tool for the native agent.

**Architecture:** One fisher-core module, `Fisher.Smt`, runs z3 or cvc5 on SMT-LIB text and parses models; `Fisher.Smt.Lake` reads and edits the project's lake files. fisher-search consumes both: the pre-pass gates the `smt` arm on the manifest, and `Fisher.Search.Disprove` gets a second source (`smt_show` query to the solver, a witness-guided certification). fisher-tools adds the `smt_check` tool; fisher-cli adds `fisher project add smt`, the doctor line and the wiring.

**Tech Stack:** Haskell (stack, LTS 22.44, hspec), lean-smt (`require smt from git "https://github.com/ufmg-smite/lean-smt.git"`), z3 and cvc5 binaries, Lake manifests.

**Spec:** `docs/superpowers/specs/2026-10-25-smt-design.md`

## Global Constraints

- No em or en dashes anywhere (code, comments, docs, commit messages); use commas, colons or parentheses.
- Config keys exactly: `fisher.smt.enabled` (default true), `fisher.smt.solver` (`auto` | `z3` | `cvc5`, default `auto`), `fisher.smt.timeout_secs` (default 10, cap 60).
- The query never goes on argv; solver stdin is `/dev/null`; output is cut at 64 KB; the process is killed at the cap plus one second.
- A project "has smt" exactly when its `lake-manifest.json` lists a package named `smt`.
- Only a kernel-certified negation is `DFalse`; a model alone is `DSuspect`.
- The fetched Lean skill and the workflow prompt texts are not edited.

## Decisions the spec leaves open

- `import Smt`: the search inserts the line `import Smt -- fisher smt` after the file's last `import` line into the base text at search start, when the project has smt and the file lacks `import Smt`; every stage then sees one consistent text. `--apply` keeps the line only when a kept proof's text contains the token `smt`; otherwise it removes it. (Prepending per stage would shift hole lines.)
- When the disproof runs: today the stage runs after a goal's second failed attempt. The SMT source is cheap (one solver process), so it runs once before the goal's first attempt; the existing late step keeps `plausible` and runs the SMT source only if the early step did not (no solver then, or lean-smt absent).
- `smt_show` versus the trace fallback: both parsers are written; the default is `smt_show`, switched by `fisher.smt.query_tactic` (`smt_show` | `trace`) so the live check can flip it without a rebuild.
- Reservoir's build list: the implementer records the actual URL and shape in the task report (as built: the Reservoir index on GitHub raw, `reservoir-index/master/ufmg-smite/smt/builds.json`, through curl), falling back to `main` with a warning when none match.

## Review Focus

1. A goal whose `smt_show` output contains an `(declare-fun f (Int) Int)` (an uninterpreted abstraction) and whose model assigns `f`: the witness tactic must not be built, and the suspect must stay `DSuspect` (Task 6 test "uninterpreted model gives no witness").
2. A model value for a `Nat` variable that is negative in the model (lean-smt encodes `Nat` as `Int` with a non-negativity side condition): the renderer must refuse the witness, not emit `(-1 : Nat)` (Task 6 test "negative Nat refused").
3. A solver that prints `sat` and then hangs before the model: the runner must return `Unknown` within the cap, not block (Task 1 test "sat without model at cap").
4. A `lake-manifest.json` that is unreadable or is version 6 (older shape with `packages` at the top level): `hasSmt` must return False and never throw (Task 2 test "manifest shapes").
5. `fisher project add smt` on a `lakefile.toml` whose last `[[require]]` block is Mathlib with a `rev` containing quotes: the appended block must be a separate block at end of file with a blank line before it (Task 4 test "toml append"; as built the block is inserted before Mathlib's instead).
